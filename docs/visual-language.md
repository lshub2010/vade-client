# Vade 客户端视觉语言（v1 · 2026-11-14）

用户要求：**美观、圆角到位、不要 Android 11 那种 Material You 味**；参考 Codex / ChatGPT / Linear 这类现代 AI 产品的前端观感。

本文件是 `vade-client` 的视觉单一来源（tokens + 组件规格 + 禁止清单）。实现落在 `skin/material/`，`miuix` / `glass` 皮肤必须遵守同一套 token 语义（值可不同，层级关系必须一致）。

---

## 一、五条原则

1. **石墨中性色 + 单一强调色**。大面积留白/留黑，颜色只出现在强调与状态上；不用 Material You 的 tonal 大面积染色。
2. **发丝线为主、阴影为辅**。静态卡片靠 hairline 分隔；浮层（悬浮 composer / 弹层 / 抽屉 / 命令面板）**必须有阴影**，主行动用辉光。精确规则见 **§8**（v2 修正：不是一刀切禁阴影）。
3. **大圆角、克制层级（v2 加大）**。圆角是这套视觉的主角：**12–36dp** 的连续刻度（v1 是 8–28，用户要求“大圆角”后整体上移一档）；不用 4–8dp 小圆角，也不用全圆角胶囊做所有东西。
4. **内容优先**。助手消息**不加气泡**（全宽文本，最大 760dp），用户消息才用右侧气泡——这样长回答读起来像文档，不像聊天气泡墙。
5. **动效短、方向明确**。150–220ms，`cubic-bezier(0.2, 0, 0, 1)`；只做位移/透明度/缩放，不做宽度高度动画。

## 三、圆角刻度

| token | dp | 用在哪 |
|---|---|---|
| `xs` | 8 | 小标签、代码块内联 |
| `sm` | 12 | 按钮（次要）、列表项、缩略图 |
| `md` | 16 | 卡片、输入框、工具卡 |
| `lg` | 20 | 用户气泡、右面板 |
| `xl` | 28 | 底部 sheet、命令面板、全屏弹层 |
| `pill` | 999 | 主按钮、chip、状态药丸 |

**禁止**：4/6dp 小圆角（Android 11 既视感）、同一屏出现超过 3 种圆角、给全宽卡片套 pill。

## 四、字号与间距

| 用途 | 字号 | 字重 | 行高 |
|---|---|---|---|
| 正文 | 15 | 400 | 1.55 |
| 次要/元信息 | 13 | 400 | 1.45 |
| 极小标签 | 11 | 500 | 1.3 |
| 列表标题 | 15 | 600 | 1.35 |
| 页面标题 | 20 | 600 | 1.3 |

间距刻度：`4 / 8 / 12 / 16 / 20 / 24 / 32`。
- 消息之间 **20**；消息内段落 **12**；卡片内边距 **16**；页面左右边距 手机 **16** / 桌面 **24**。
- 触摸目标 ≥ **44×44**；图标 20dp，点击区外扩 12dp。

## 五、组件规格

| 组件 | 规格 |
|---|---|
| **消息（助手）** | 无气泡、无边框；宽 ≤760dp；Markdown 渲染；代码块 `surfaceSunken` + `sm` 圆角 + 顶部语言标签 |
| **消息（用户）** | 右对齐；`surface` 底 + `hairline`；`lg` 圆角，右下角 6dp（气泡尾）；最大宽度 78% |
| **输入框** | `md` 圆角；`surface` 底 + `hairline`；聚焦时 2dp `accent` 描边（不是发光）；多行最高 6 行后内部滚动 |
| **主按钮** | `pill`；`accent` 底 + 白字；禁用：`textMuted` @ 30% 底 + 无描边 |
| **次要按钮** | `sm` 圆角；透明底 + `hairline`；hover/selected 加 `accentSoft` |
| **工具卡** | `md` 圆角 + `hairline`；左侧 3dp 状态条（成功 `success` / 失败 `danger` / 审批 `warn`）；成功默认折叠，只显示一行摘要 + 耗时；失败展开并显示错误摘要 |
| **附件 chip** | `sm`；缩略图 28×28 `xs` 圆角；名称 13sp；超出省略 |
| **列表项** | `sm` 圆角；选中/悬停 `accentSoft`；行高 56（桌面 48） |
| **底栏** | 高 64 + 安全区；背景 `surface` @ 92% + 顶部 `hairline`；选中项 icon 20 + 文字 11；不做 Material 的浮动 pill 选中块 |
| **弹层/sheet** | `xl` 顶部圆角；`surfaceRaised`；投影 `0 8 24 rgba(0,0,0,.18)`；遮罩 `rgba(0,0,0,.32)` |

## 六、动效

| 场景 | 时长 | 曲线 |
|---|---|---|
| 面板/弹层进出 | 200ms | `cubic-bezier(0.2,0,0,1)` |
| 列表项 hover/选中 | 120ms | 同上 |
| 消息出现 | 160ms 淡入 + 4dp 上移 | 同上 |
| 流式光标 | 1s 循环呼吸 | `ease-in-out` |

`prefers-reduced-motion` / 系统“减少动画”开启时：只保留透明度变化，时长 100ms。

## 七、明确禁止（Android 11 / Material You 味）

1. 大面积 tonal 色块（整块紫色/绿色背景表示层级）。
2. 56dp 纯色 AppBar + 大标题下沉滚动。
3. 4dp elevation 阴影堆叠（卡片、按钮都带影子）。
4. FAB（悬浮圆按钮）——新建入口用顶栏 ✎ 或快捷键。
5. Material 默认紫 `#6750A4` 及其 tonal 派生。
6. 圆角 < 8dp、或全屏 ripple 大扩散。
7. 用 emoji 当图标。
8. 边框 + 阴影 + 底色三者同时用在一个静态卡片上。

## 八、落地与验收

- 实现：`skin/material/` 的 `MaterialSkin` 颜色/形状对象 + 组件内部 padding；`skin/miuix`、`skin/glass` 按同一 token 语义取值。
- 验收（每轮视觉改动都要过）：
  1. 对比度脚本或目测：正文/次要文本 ≥ 4.5:1（亮暗两套）。
  2. 圆角清单：同屏 ≤3 种；无 <8dp。
  3. 触摸目标 ≥44×44（桌面用 32 最小，鼠标可接受）。
  4. 截图对照：手机 480×900、桌面 1280×800 各 ≥3 张，**逐张开图**，确认没有 Material 默认紫、没有 Material 的 4dp elevation 阴影（浮层阴影按 §8 的参数，不算违规）。
  5. `MaterialImportGuardTest` 仍绿（业务页面不得直接 import material3）。

# v2 · 2026-11-14 用户口径（覆盖以上任何冲突处）

用户对第一版截图给的原话：**「界面可以稍微做高级些。对话框要一直悬浮的，发送按钮另外在对话框旁边有一个小球。按钮图标不要用文字。批准放入会话内，不做弹出，要不然会干扰其他会话。全局元素都要有背景模糊。」** 以及 **「要 miuix 的风格，但是也要新颖高级」**。

七条硬要求，全部可验收：

## 1. 输入框常驻悬浮（floating composer）
- 不再贴底占满一行：它是一个**独立浮层**，左右各留 16dp（桌面 24dp），距底安全区 16dp。
- 形状：`xl` = 28dp 圆角（多行时同圆角，不做胶囊变形）；背景 = 玻璃层（见 §5），描边 1px `hairline`，**并带浮层阴影**（§8：它是浮层，不是静态卡片）。
- 列表底部内边距 = composer 实测高度 + 24dp，滚到底时最后一条消息不被遮住；键盘弹出时浮层随 `imePadding` 上移，列表不动画跳跃。
- 输入框内不再放发送按钮；只放：左侧附件图标、文本域、右侧字符计数（可选）。

## 2. 发送球（独立于输入框）
- 一个 **48dp 正圆**，位于 composer **右侧、垂直居中**，与输入框间距 12dp；不与输入框同容器背景（它是独立元素）。
- 有内容：`accent` 实心 + 向外 12dp 柔光（`accent` 24% alpha），图标反白。
- 空内容：`surfaceGlass` + 1px `hairline`，图标 `muted`；此时仍可点（触发提示），不闪烁。
- 生成中：同一球位变**停止**（方形图标），点击中断；球保持 `danger` 色但只染图标与描边，不整球变红（避免视觉噪音）。
- 按压：`scale 0.92`，180ms，`cubic-bezier(0.2,0,0,1)`；松手回弹。
- 禁止：球里写字（"发送"）、球做成长条、球与输入框连成一体。

## 3. 图标即按钮（no text buttons，**2026-11-14 加严**）

用户原话：「选项的图标不要用文字，用图标」。

### 3.1 必须是矢量图标，不是字符

**禁止**把 Unicode 字符当图标画出来——包括但不限于：
- 箭头符号 `↑ ↓ ← → ▲ ▼`
- 几何符号 `■ □ ● ○ ◆`
- 数学/杂项符号 `＋ ⋯ ✕ ✓ ▾ ▸ ‹ ⌕ ✎ •`
- **汉字当图标**（当前 `Destinations.kt` 的四个目的地就是这么做的，写着 "until a real icon pack lands in U1-g"）
- emoji

**唯一允许的形态**：`ImageVector`（Compose 的矢量图），由 `vade.ui.icon` 包统一提供。

理由：字符图标有三个真问题——① 不同平台/字体的字形宽度与基线不一致，同一套界面在 Android/桌面/Wasm 上会错位；② 无法控制线宽与视觉重量，汉字和符号混排时粗细不齐；③ 字符会跟随 `fontSize` 缩放，和图标应有的固定尺寸语义冲突。

### 3.2 图标库：Tabler Icons（2026-11-14 用户选定）

| 项 | 值 |
|---|---|
库 | **Tabler Icons** — https://tabler.io/icons |
许可证 | **MIT**（商用、修改、再分发均可，保留版权声明） |
数量 | 6287（5233 描边 + 1054 填充） |
规格 | **24×24 网格、2dp 描边** —— 与本节要求一字不差 |

- 一律通过 `vade.ui.icon.VadeIcons` 暴露，**业务代码不得直接 import `com.composables.icons.tabler.*`**（换库时只改一处）。
- 实际绘制 **20dp 或 24dp** 两档；颜色由调用方 `tint`，图标本身不带色。

### 3.4 无障碍与触摸

- 纯图标按钮必须有 `contentDescription`（中文，如「发送」「停止生成」）。
- 触摸区 ≥44dp（桌面 ≥32dp），图标本身可以小于触摸区。
- 例外：破坏性确认（删除会话）可以带文字；首次引导的主行动可以带文字。

### 3.5 禁止

- 禁止 emoji 当图标。
- 禁止同一屏混用两套线宽或两种风格（描边 + 填充混用）。
- 禁止为了省事在图标位置 `Text("↑")`。
- 禁止直接依赖 `compose.materialIconsExtended`：该 artifact 最新只到 1.7.3，与 CMP 1.12 搭配有解析风险；图标一律自建在 `vade.ui.icon`。

## 4. 审批内联（inline approval，不弹窗）
- 审批**不进 Overlay/S dialog**，作为**会话时间线里的一张卡**插在触发它的位置：卡头是「需要批准」+ 风险徽标，卡体是参数摘要（脱敏后的 `args_preview`），卡尾是图标按钮（✓ 允许 / ✕ 拒绝 / ⏷ 详情）。
- 影响范围：**只影响当前会话**；其它会话、其它会话的输入框、底栏都不被遮挡，不抢焦点，不暂停滚动。
- 状态就地演进：待审批 → 已允许/已拒绝（同一张卡变结果态 + 时间戳），**不新增一条消息**；超时变「已超时」。
- 待审批卡出现时，composer 不禁用；用户可以先继续打字（提交时若该会话仍有待审批，按 core 的排队语义）。
- 允许通过普通滚动离开视野；未处理时列表顶部/会话列表可显示一个小圆点提示（不做全局红点）。
- 保留 `ApprovalDialog` 组件给**模块页面/管理面**用；聊天流里不用它。

## 5. 全局背景模糊（真 blur，不是 alpha 渐变）
- 用 **Haze 2.1.0**（`dev.chrisbanes.haze:haze-blur`），已验证有 `androidApiElements` / `jvmApiElements` / `wasmJsApiElements` 三种产物，Android/桌面/Wasm 同一套语义。
- 必须模糊的层：顶栏、底栏（导航）、悬浮 composer、底部弹层、侧栏/抽屉、搜索结果浮层、图片预览的控制条。
- 参数：`blurRadius = 24dp`（弹层 32dp），**必须是高斯模糊**：背后的内容要被模糊但**仍能看见**——能分辨出「那里有字/有图」，读不出具体内容。这是验收重点，不是"磨砂白板"。
- 玻璃层染色极薄：亮色 `#FFFFFF` @ **26%**、暗色 `#0E0E10` @ **34%**（可在此范围上下浮动 6%，但不能超过 45%）。染色只用来保证前景文字对比度，不得把背景盖死。
- **染色必须走 `colorEffects(listOf(HazeColorEffect.tint(tint)))`**。`HazeBlurStyle.backgroundColor(...)` 画在不透明模糊层**之后**，视觉上完全无效——探针实测：用它时玻璃是未染色的原始模糊均值，把标题洗到 2.15:1、副标题洗到 1.17:1，看起来像"文字发虚"，实际是染色没生效。
- **前景不会被模糊**：`hazeBlur` 只过滤 backdrop，节点内容始终无滤镜绘制。不要为了"让文字清晰"去把玻璃和内容拆成两层——探针实测这样改 PNG 的 md5 完全不变，是白做工。
- **玻璃必须与 canvas 同色系**：背后若是饱和彩色内容，26%/34% 的染色盖不住，玻璃会读成"背后内容的水色"而不是"应用表面"。真实界面背景是石墨中性色，不触发此问题；但模块页面/图片预览这类背后有强色的场景，tint 要按实际背景加深。
- **发丝线在高对比背景下要加深**：1px `hairline` 在花哨背景上会看不见，玻璃就像"直接糊上去"。这类场景用 `hairline` 加深一档，或改用 1.5px。
- 前景文字压在玻璃上时，靠 `hairline` + 文字自身的对比度立住，不靠加深玻璃底。
- 模糊层与内容之间必须有 **1px `hairline`** 界定，禁止纯透明玻璃无边界。
- **禁止**用垂直 alpha 渐变假装模糊（U1-a 的底栏就是这么做的，v2 必须换掉）。
- 反面判据（截图直接判）：如果玻璃区域背后**完全看不出任何形状/文字轮廓**，就是染色过重，判不通过；反之如果字清晰可读，就是没模糊。
- 性能：模糊层数 ≤3 个同屏；滚动时不重建 `HazeState`；Wasm 上实测帧率不低于无模糊版本的 80%。

## 6. Miuix 风格 + 新颖
- 保留 Miuix 的：大圆角、舒展留白、克制的分隔、单强调色。
- 不要 Miuix/HyperOS 的：白底卡片层层堆叠、彩色 tonal 块、控制中心式大圆角方阵。
- 新颖点落在**玻璃层 + 悬浮输入区 + 单球行动**三件事上：界面大部分是"空"和"字"，操作元素浮在玻璃上。

## 7. 动效（全部 150–220ms）
- 发送球按压缩放；发送后球体做一次 8dp 上浮 + 回位（仅一次，不循环）。
- 多行输入框高度动画 200ms（跟随内容，不跳变）。
- 审批卡内联插入：fade + 12dp 上滑，180ms；变结果态只做颜色过渡，不位移。
- 列表滚动时模糊层不重绘（`HazeState` 提到稳定作用域）。

## 验收（v2 追加）
6. 截图必须能看出：输入框是**浮**的、球在框外、按钮全是图标、审批卡在会话里、栏位有真模糊（背景内容可见但模糊）。
7. 截图缺陷清单逐条签收：无文字按钮、无 Overlay 审批、无 alpha 渐变假模糊、无 Material 紫、无 Material 4dp elevation；且浮层**有**阴影/辉光、全局弹窗**有**顶部白条手柄与四周空隙。
8. **不检查运动模糊**（§11 已废弃，v2 不做）。


## 8. 阴影 / 辉光（v2 · 2026-11-14 加严：必须是渐变 + 有方向）

用户原话：**「阴影这些都是有渐变的，不是后面糊一层就完事，然后阴影有方向」**。

### 8.1 三条硬规则

1. **阴影是多层渐变叠加，不是单层半透明色块**。一层 `rgba(0,0,0,.18)` 铺在元素下面 = 糊一层，必须禁止。真实阴影是**至少 3 层**、每层不同 blur 与不同 alpha 叠加出的连续衰减。
2. **阴影有方向**：光源固定在**正上方偏前**（`offsetY` 为正，`offsetX` 为 0 或极小）。阴影只往**下方**扩散，元素上方**不得有阴影**。
3. **阴影随层级递增**，不是所有浮层用同一套。层级越高，blur 越大、扩散越远、alpha 越低（更柔和）。

### 8.2 五级阴影（可直接落地的参数）

| 级别 | 用途 | 层 1 | 层 2 | 层 3 |
|---|---|---|---|---|
`shadow0` | 页面内静态卡（工具卡、附件卡、审批卡） | `0 1 2 rgba(0,0,0,.05)` | `0 2 4 rgba(0,0,0,.03)` | — |
`shadow1` | 列表项悬停、chip | `0 2 4 rgba(0,0,0,.06)` | `0 4 8 rgba(0,0,0,.04)` | — |
`shadow2` | 悬浮 composer、搜索浮层 | `0 4 8 rgba(0,0,0,.07)` | `0 8 16 rgba(0,0,0,.05)` | `0 12 24 rgba(0,0,0,.03)` |
`shadow3` | 全局弹窗 sheet、抽屉 | `0 8 16 rgba(0,0,0,.09)` | `0 16 32 rgba(0,0,0,.06)` | `0 24 48 rgba(0,0,0,.04)` |
`shadow4` | 图片预览控制条、临时 toast | `0 12 24 rgba(0,0,0,.11)` | `0 24 48 rgba(0,0,0,.07)` | `0 32 64 rgba(0,0,0,.05)` |

**暗色主题**：alpha 各层 × 1.8，blur 半径 × 1.2（暗底上阴影要更深更散才看得见）。

**实现方式**：Compose 的 `Modifier.shadow(elevation, shape, ambientColor, spotColor)` 只有单层——**不够**。必须用 `drawBehind` 手动画多层：

```kotlin
fun Modifier.layeredShadow(spec: ShadowSpec, shape: Shape) = drawBehind {
    spec.layers.forEach { layer ->
        drawIntoCanvas { canvas ->
            canvas.drawOutline(
                outline = shape.createOutline(size, layoutDirection, this),
                paint = Paint().apply {
                    color = layer.color
                    asFrameworkPaint().apply {
                        maskFilter = MaskFilter.makeBlur(FilterBlurMode.NORMAL, layer.blurRadiusPx)
                        // 方向性：只往下偏移
                        this.color = android.graphics.Color.TRANSPARENT
                    }
                },
                // 偏移由 translate 完成
            )
        }
    }
}
```
（具体 API 在 Compose MP 上要用 `Skia` 路径，桌面/Wasm/Android 都能走 `Paint.asFrameworkPaint()` 的 `MaskFilter`；实现时以能编译、真出图为准。）

### 8.3 方向性细则

- `offsetY` 与 `blur` 的比例约 **1 : 2**（例：`shadow2` 的层 2 是 `offsetY=8, blur=16`）。
- `offsetX` **恒为 0**（界面是正上方光源，不玩斜射）。
- **元素上方不得有阴影**：如果画出来顶部有暗边，说明用了对称 blur 且没偏移，必须修。
- 玻璃层（`GlassSurface`）的阴影**画在玻璃外面**，不能画在玻璃里面（否则会污染模糊采样）。

### 8.4 辉光（glow）与阴影不是一回事

- **辉光**用于「主行动」与「当前活跃」（发送球、当前会话指示），是**彩色、向外扩散、无偏移**（对称），且**两层**：内层亮、外层淡。
- 参数：`0 0 12 accent@32%` + `0 0 28 accent@16%`。
- **禁止**给高风险审批卡加红色辉光（会吵），它只用 `shadow0` + 左侧 3dp `danger` 状态条。

### 8.5 禁止清单

- 单层半透明色块当阴影（"糊一层"）。
- 对称 blur 且 `offsetY=0`（没有方向）。
- 元素上方出现阴影。
- 彩色阴影（除辉光）。
- 同一元素同时出现：粗边框 + 强阴影 + 重底色（发丝线 + 浅阴影 + 底色是允许的组合）。

## 9. 全局弹窗 = 悬浮卡片（不是贴边、不是全屏对话框）

所有全局弹出（审批详情、模型选择、设置、附件预览、危险确认）统一成 **floating sheet card**：

- **四周留空隙**：左右各 **12dp**、底部 **12dp** 与屏幕边距；**永远不贴边、不满宽**。
- 圆角：上 **28dp**、下 **28dp**（四角同圆），形成"一张卡浮在内容上"。
- 背景：玻璃层（§5 高斯模糊 + 26%/34% 染色）+ 浮层阴影（§8）+ 1px 发丝线。
- **顶部中央有一个小白条（grabber）**：`36×4dp`、圆角 `2dp`、白色 70% alpha（暗色）/ 黑 24% alpha（亮色），距卡顶 **8dp**；它的唯一职责是告诉用户"这是可下拉关闭的弹窗"，**不做其他装饰**。
- 交互：下拉超过 **80dp** 或超过速度阈值即关闭；点遮罩关闭；`Esc` 关闭；键盘弹出时卡片整体上移，不改变圆角。
- 遮罩：`rgba(0,0,0,.24)` + 背景模糊（不是纯黑 60%），保证背后的会话仍"隐约可见"。
- 卡片内部结构固定：`grabber → 标题行（图标 + 标题 + 关闭 ✕）→ 内容区（可滚）→ 行动区（图标按钮）`。
- 同一时刻**只允许一个** global sheet；不叠层。


## 10. 大圆角刻度（v2 覆盖 §三）

| 名字 | 值 | 用在哪 |
|---|---|---|
| `xs` | 12dp | chip、徽标、小按钮、代码块内联片段 |
| `sm` | 16dp | 列表行、次要按钮、输入框内层 |
| `md` | 20dp | 工具卡、附件卡、搜索结果行 |
| `lg` | 24dp | 用户消息气泡、图片缩略、模块卡片 |
| `xl` | 28dp | 悬浮 composer、主卡片 |
| `sheet` | 32dp | 全局弹窗卡片（四角同圆） |
| `pill` | 全圆 | 只给主行动按钮、状态标签 |

规则：
- **同一屏可见圆角 ≤3 种**；相邻层级至少差 4dp，否则看起来像没对齐。
- 卡片最小 16dp；列表行如果嵌套卡片，外层 ≥ 内层 + 4dp（否则视觉上"陷进去"）。
- 圆角必须是**等比**（`RoundedCornerShape(dp)`，不用百分比），保证不同尺寸下观感一致。
- 图片/缩略图统一 `24dp`；头像用全圆。

## 11. 动画的运动模糊 —— **已废弃（2026-11-14 用户决定不做）**

用户原话：「动态模糊不要算了吧，感觉没啥用」。

**结论：v2 不做运动模糊。** 这一节保留作为决策记录，实现时不要照做。

废弃理由（都有实测依据，见 `shots/motion/RESULT.md`）：

1. **物理真实与可读性不可兼得**：6000 dp/s 下每帧位移约 100dp，真实运动模糊会彻底抹掉字形；而要保住可读性，半径必须压到 1.5–2dp，那个量级肉眼几乎看不出"在动"。
2. **6dp 实测毁掉内容**：`real-box-6.png` 上 20sp 标题一个都认不出、13–15sp 正文全变条形码，`lap_var` 只剩锐利的 24%。
3. **box 核在等宽周期文字上有拍频**：34sp 病理夹具上出现 3–4 道等距回音（真实内容不明显，但说明核长与字形间距会打架）。
4. **收益与复杂度不成正比**：要跨三端各写一套 actual（Android `Modifier.blur` 无核参数、桌面/Wasm 走 Skiko `ImageFilter`），还要处理 Android ≤30 降级，换来的只是一个"几乎看不出"的效果。

**决定性证据（1.5dp vs 6dp 对照）**：

| 半径 | 可读性 | 效果可见度 | 判定 |
|---|---|---|---|
| 1.5dp | 完全可读（`real-box-1.5.png` 上所有标题与正文锐利） | **几乎看不出任何拖影** | 无意义 |
| 3.0dp | 勉强可辨 | 能看出拖影 | 不可接受 |
| 6.0dp | **全毁**（`real-box-6.png` 20sp 标题认不出、正文变条形码） | 明显 | 不可接受 |

**中间不存在"既看得出在动、又读得下去"的档位** —— 这是砍掉它的决定性理由。

**替代方案**：用**位移与透明度**表达速度感就够了——列表快速滚动时自然有位移，不需要额外加模糊。§1 的五条原则里"只做位移/透明度/缩放"这条本来就已经覆盖了需求。

**代码处置**：`skin/glass/MotionBlur*.kt` 四个文件保留（已被 `motion-probe` 与 43 条测试引用），但**产品代码不得调用**；`SkinMotion` 里的 `motionBlurMaxRadiusDp` 等字段保留为常量，不作为功能开关。若后续要清理，需同时删探针与测试。

## 13. 卡片左侧强调色竖条（工具卡 / 审批卡）

用户要求：**「那个工具和审批前那个高亮强调色竖条，上方要跟着圆角稍微弯一点然后变细消失」**。

### 13.1 形状

不是一根等宽的直条。它是一条**沿卡片左边缘走的描边**：

1. **顶部**：从卡片圆角起点开始，**顺着圆角弧线弯曲**（跟随 `shape` 的 topLeft 半径），不是直角切进去。
2. **上段**：弧线结束后向下延伸，**宽度从 3dp 渐变到 0**（变细）。
3. **中段**：最宽处 3dp，直行。
4. **下段**：再次**从 3dp 渐变到 0**，在卡片高度约 60–70% 处**消失**（不要走到卡片底边）。

整体观感：像一道光从左边缘上方斜着扫下来然后淡出，而不是"贴了一条胶带"。

### 13.2 参数

| 项 | 值 |
|---|---|
最大宽度 | **3dp** |
顶端 | 从圆角弧线起点开始，**沿弧走**（弧长 = 卡片圆角半径） |
渐变 | 顶部 8dp 内 3dp → 0；底部 12dp 内 3dp → 0 |
消失位置 | 卡片高度的 **60–70%**（不要到底） |
颜色 | 成功 `success` / 失败 `danger` / 审批 `warn`（与卡片状态一致） |
不透明度 | 中段 100%，两端渐隐到 0 |

### 13.3 实现要点

- 用 `Modifier.drawWithContent` + `Path` 手绘，**不要**用 `Box(width=3dp)` 那种矩形块（做不出圆角跟随与渐变）。
- 路径要 `clip` 到卡片 shape 内（否则弧线会溢出）。
- 渐变用 `Brush.verticalGradient` 或沿路径的 `Brush`；**宽度变化**用可变宽度路径（`Path` 的两条边分别收拢），不是靠 alpha 假装变细。
- 桌面/Wasm/Android 用同一套 `Path` 代码（纯 Compose graphics，无平台差异）。

### 13.4 禁止

- 等宽直条（"贴胶带"）。
- 顶端直角切进圆角。
- 一直画到卡片底边。
- 用 alpha 渐隐代替宽度变细（那是"变淡"，不是"变细"）。
